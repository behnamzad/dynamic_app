# Shared personalization

این بخش احتمال خرید را از `PredictionManager` می‌گیرد و آن را به یک تغییر ساده در UI تبدیل می‌کند. خودش Widget نمی‌سازد و به صفحه خاصی وابسته نیست.

مرزهای سه حالت در زمان آموزش از صدک‌های ۳۳ و ۶۶ احتمال‌های کالیبره‌شده Validation ساخته و داخل `preprocessing.json` ذخیره می‌شوند:

- یک‌سوم پایین احتمال‌ها: نمایش محصولات جایگزین؛
- یک‌سوم میانی: برجسته کردن نظرات و مشخصات؛
- یک‌سوم بالا: برجسته کردن دکمه افزودن به سبد.

هر سه حالت با آیکون هوش مصنوعی، گرادیان بنفش و آبی و انیمیشن ورود کوتاه از ظاهر معمول صفحه جدا می‌شوند. متن UI روشن می‌کند که این بخش با تصمیم مدل تغییر کرده، ولی درصد احتمال خرید را نشان نمی‌دهد. اگر انیمیشن‌های دستگاه خاموش باشند، این حرکت‌ها هم اجرا نمی‌شوند.
از زمان شروع Prediction تا آماده‌شدن تصمیم، صفحه بدون مسدودشدن باز می‌ماند و یک کارت تحلیل هوش مصنوعی نمایش داده می‌شود. نتیجه آماده‌شده با یک جابه‌جایی نرم جای همین کارت را می‌گیرد.

Flutter مرزها را همراه همان نسخه مدل می‌خواند؛ بنابراین آموزش یک مدل سازگار به تغییر دستی کد کلاینت نیاز ندارد. مدل‌های قدیمی که این بخش را ندارند با مرزهای قبلی ۲.۵٪ و ۵٪ اجرا می‌شوند.

`PersonalizationManager` خودش احتمال محصول، مرزهای مدل و محصولات جایگزین را می‌گیرد و نتیجه آماده را به `ProductInfoBloc` می‌دهد. Bloc فقط روی Action تصمیم سوییچ می‌زند و دیگر به `PredictionManager` یا `ProductPrediction` وابسته نیست. صفحه محصول هر سه Action را با `recommendation_requested` ثبت می‌کند و `next_action` همان Action اجراشده است. احتمال فقط در telemetry داخلی ذخیره می‌شود و در UI نمایش داده نمی‌شود.

اگر کاربر یکی از محصولات جایگزین را باز کند، `RecommendationAttribution` شامل request ID، رتبه، slot، strategy، نسخه مدل و
confidence وارد صفحه محصول می‌شود. اولین افزودن موفق آن محصول، `recommendation_cart_add` را ثبت می‌کند و attribution به‌شکل
محلی کنار آیتم سبد می‌ماند. خرید موفق نیز برای همان آیتم `recommendation_purchase` ثبت می‌کند. این داده محلی بعد از refresh سبد
یا شروع دوباره برنامه هم قابل بازیابی است و پس از حذف کامل آیتم یا خرید موفق پاک می‌شود.

برای اینکه صفحه محصول دوباره شلوغ نشود، مسئولیت‌ها جدا شده‌اند: `ProductInfoPage` فقط وضعیت Bloc، چرخه عمر صفحه، کارهای
کاربر و انیمیشن را هماهنگ می‌کند؛ `ProductInfoContent` و Widgetهای کوچک‌تر ظاهر صفحه را می‌سازند؛ و
`ProductInfoBehaviorTracker` وضعیت موقت ثبت رفتارهای صفحه، سبد و پیشنهادها را نگه می‌دارد.
